# Docker Services

Three services in `docker-compose.yml`. Two custom-built images, one pulled directly.

## Services

### `stun` — coturn/coturn

Pulled from Docker Hub, not built locally. Runs in STUN-only mode (`--stun-only`); no TURN relay, no auth, no TLS. Purpose is purely to help WebRTC ICE find the host machine's LAN IP.

The `--external-ip=${HOST_IP}` flag tells coturn what IP to advertise to clients. Without a correct `HOST_IP` in `.env`, ICE candidate discovery will fail and streams will not play.

Ports exposed: `${STUN_PORT:-3478}` on both UDP and TCP.

### `mediamtx` — rtsp-kiosk-mediamtx

Built from `Dockerfile.mediamtx`. Base image is `bluenviron/mediamtx:1.16.3-ffmpeg` (pinned). Alpine packages `jq` and `gettext` (for `envsubst`) are added at build time. The image has no `mediamtx.yml` baked in — config is generated at startup.

The entrypoint is `generate-config.sh`, which runs before MediaMTX and then `exec`s into it.

`./data` is bind-mounted to `/data` inside the container. This is how `streams.json` and `mediamtx-base.yml` are read in, and how `mediamtx.yml`, `streams-public.json`, and `views-public.json` are written back to the host.

Ports exposed:

| Port | Protocol | Purpose |
|------|----------|---------|
| 8554 | TCP | RTSP ingest |
| 8000 | UDP | RTSP RTP |
| 8001 | UDP | RTSP RTCP |
| 8889 | TCP | WebRTC/WHEP HTTP |
| 8189 | UDP | WebRTC ICE |
| 9997 | TCP | MediaMTX API |

`depends_on: stun` — ensures coturn is up before MediaMTX starts, though there is no health-check; it is a best-effort ordering.

### `nginx` — rtsp-kiosk-ui

Built from `Dockerfile.ui` (two-stage). Stage 1 uses Node 20 to install npm deps and bundle `mqtt.min.js` into `www/`. Stage 2 copies the result into `nginx:alpine` alongside `nginx.conf`.

The Dockerfile does not set an entrypoint — it is overridden in `docker-compose.yml` to run `envsubst` first, then nginx. This means the image alone cannot start correctly without the compose entrypoint.

`streams-public.json` and `views-public.json` are bind-mounted read-only from `./data` over the top of the baked-in files (which don't exist in the image — they're generated by the mediamtx container at startup). This creates an implicit runtime dependency: nginx mounts files that only exist after the mediamtx container has run `generate-config.sh` at least once.

`depends_on: mediamtx` provides ordering, but there is no guarantee `generate-config.sh` has finished before nginx reads the files.

## Startup Sequence

```
docker compose up
  └─ stun starts
  └─ mediamtx container starts
       └─ generate-config.sh runs
            reads  data/streams.json
            reads  data/mediamtx-base.yml
            writes data/mediamtx.yml
            writes data/streams-public.json
            writes data/views-public.json
       └─ exec /mediamtx data/mediamtx.yml
  └─ nginx container starts
       └─ envsubst injects env vars into index.html
       └─ nginx -g 'daemon off;'
            mounts data/streams-public.json → /usr/share/nginx/html/streams.json
            mounts data/views-public.json   → /usr/share/nginx/html/views.json
```

## Dev vs Prod

`docker-compose.dev.yml` is an overlay applied with `-f docker-compose.dev.yml`. It only overrides the `nginx` service.

| Difference | Prod | Dev |
|------------|------|-----|
| Port | 80 | 8080 |
| Entrypoint | `envsubst` then nginx | `nginx` directly (no envsubst) |
| `index.html` | Baked into image, env vars substituted at start | Bind-mounted from `./www/index.html` |
| `app.js` | Baked into image | Bind-mounted from `./www/js/app.js` |
| `streams.json` | Bind-mount from `./data/streams-public.json` | Same |
| `views.json` | Bind-mount from `./data/views-public.json` | Same |
| MediaMTX / STUN | Running | Not started by dev overlay |

In dev, `$VAR` literals from unsubstituted env vars remain in `index.html`. The JS in `app.js` handles these gracefully (treats them as falsy/empty values).

Frontend changes (HTML, JS, CSS) take effect immediately without a rebuild. Data file changes (`streams.json`, `views.json`) also reflect immediately.

## Rebuild and Restart Rules

| Change | Action needed |
|--------|---------------|
| `data/streams.json` or `data/mediamtx-base.yml` | Restart `mediamtx` container |
| `nginx.conf` | Rebuild `nginx` service |
| `www/` files | Rebuild `nginx` service (prod); no action needed in dev |
| `Dockerfile.ui` | Rebuild `nginx` service |
| `Dockerfile.mediamtx` or `scripts/generate-config.sh` | Rebuild `mediamtx` service |
| `.env` (`HOST_IP`, `STUN_PORT`) | Restart all services |
